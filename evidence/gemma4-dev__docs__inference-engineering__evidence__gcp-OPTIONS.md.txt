51: #### 4 — Cloud Run with a GPU
52: 
53: - L4 (24 GB) or RTX PRO 6000 (96 GB), one per instance. An L4 needs at least 4 CPU and 16 GiB. Driver 580.x, CUDA 13.0. [GPU services](https://docs.cloud.google.com/run/docs/configuring/services/gpu)
54: - Scales to zero. Billing is per instance lifetime, with nothing charged while no instance exists. Google quotes about 5 seconds to start an instance before the container and model load. [GPU services](https://docs.cloud.google.com/run/docs/configuring/services/gpu)
55: - Zonal redundancy is on by default and costs more per GPU-second; off is cheaper, and its quota is more likely to be granted. The first deployment gets 3 L4s per region with redundancy off. [GPU services](https://docs.cloud.google.com/run/docs/configuring/services/gpu)
56: - Set Cloud Run concurrency to vLLM's `--max-num-seqs`: requests queued inside vLLM do not trigger scale-out. [Run Gemma on Cloud Run](https://docs.cloud.google.com/run/docs/run-gemma-on-cloud-run)
57: - Weights load faster from Cloud Storage than from Hugging Face; Google recommends a Cloud Storage volume or a parallel copy. [GPU best practices](https://docs.cloud.google.com/run/docs/configuring/services/gpu-best-practices)
58: - Private by default here: `--no-allow-unauthenticated`, called with `gcloud auth print-identity-token`.
59: - **Measured:** deploy to serving 6.6 minutes; from zero, the waking request was answered after 361.8 s and 483.2 s with default settings, 240.1 s with warm caches on a Cloud Storage volume (`results/2026-10-12/launch-to-ready.txt`, `coldstart.txt`, `coldstart-all.txt`). The deploy uses `VLLM_ENABLE_CUDA_COMPATIBILITY=0`: with the image's forward-compatibility libraries switched on, vLLM fails on Cloud Run's 580 driver with CUDA error 803.

70: #### 6 — Compute Engine GPU VM
71: 
72: - G2 (L4) and G4 (RTX PRO 6000) are Google's picks for real-time serving; A3 (H100) and up for larger models. [Accelerator-optimized machines](https://docs.cloud.google.com/compute/docs/accelerator-optimized-machines)
73: - `g2-standard-4`: 4 vCPU, 16 GB, one L4 with 24 GB at 300 GBps. [GPUs](https://docs.cloud.google.com/compute/docs/gpus)
74: - Spot (up to 91% off, preemptible), flex-start VMs (up to 7 days, waits for capacity) and calendar-mode reservations change price and availability. [Spot](https://docs.cloud.google.com/compute/docs/instances/spot), [Flex-start VMs](https://docs.cloud.google.com/compute/docs/instances/about-flex-start-vms), [Calendar mode](https://docs.cloud.google.com/compute/docs/instances/future-reservations-calendar-mode-overview)
75: - The `common-cu129-ubuntu-2204-nvidia-580` Deep Learning VM image booted on `g2-standard-4` with driver 580.178.04 and the NVIDIA container toolkit installed, and Docker missing. Google's machine page says Deep Learning VM images cannot boot G2; on 2026-10-12 this one did.
76: - No public port: the VM is reached through an IAP TCP tunnel.
77: - **Measured:** 13 zones in 5 regions refused `g2-standard-4` with `STOCKOUT` before `northamerica-northeast1-b` launched one, with 16 L4s of quota in every US region (`results/2026-10-12/capacity.txt`).

79: #### 7 — Cloud TPU
80: 
81: - The Cloud TPU API is no longer under active development; TPU7x (Ironwood) and later are Compute Engine or GKE only. Compute Engine supports v5p, v6e and TPU7x, so v5e stays on the TPU API or GKE. [TPUs in Compute Engine](https://docs.cloud.google.com/compute/docs/tpus/tpu-resources-in-compute-engine)
82: - v6e: 32 GB HBM at 1638 GBps; bf16 918 TFLOPs, int8 1836 TOPs; fp8 at the bf16 rate. TPU7x: 192 GB at 7380 GBps, fp8 at twice bf16. [v6e](https://docs.cloud.google.com/tpu/docs/v6e), [TPU7x](https://docs.cloud.google.com/tpu/docs/tpu7x)
83: - vLLM runs on TPU through the `tpu-inference` plugin, tool calls included. Its JAX path serves int4-weight (`w4a16`) checkpoints for dense layers since 2026-09-27; this repo serves the bf16 checkpoint on TPU. [tpu-inference](https://github.com/vllm-project/tpu-inference)
84: - Flex-start (DWS) draws on a separate pool, stops by itself, and costs less. [DWS on GKE](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/dws)
85: - **Measured:** v6e-1 was refused in every zone this project can use, on-demand and Spot, and a v6e flex-start request stayed queued. A v5e-1 flex-start request in us-west4-a got a node in 22 seconds; vLLM TPU 0.30.0 served the bf16 checkpoint with tool calls, 20 of 20, at 144.1 tok/s server-side (`results/2026-10-12/capacity.txt`, `server-side-tpu.txt`).
