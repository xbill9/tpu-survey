1: # 2026-10-02-tp-vs-replicas-v5e4
2: 
3: Which way of using the four chips of a v5e-4 serves `xbill9/gemma-4-E2B-it-qat-w8a8-int8` fastest. Every layout ran on
4: one VM, one boot: flex-start `v5litepod-4` in `us-west4-a`, created through this rig's own `create_tpu_queued_resource`,
5: on the patched image the boot script builds (`vllm-tpu-w8a8:patched`). Each later container reuses the boot container's
6: image, environment (`MIN_TOKEN_BUCKET=64`, `GMM_V2_TILE_VMEM_FRACTION=0.85`) and `vllm serve` arguments
7: (`--max-model-len 16384 --max_num_batched_tokens 512 --gpu-memory-utilization 0.80`, the gemma4 tool and reasoning
8: parsers), changing only what its row names.
9: 
10: #### Result
11: 
12: - 🟢 **Four one-chip engines are the fastest layout**, and `--data-parallel-size 4` delivers them behind one port: 2.52x
13:   TP=4's output at 64 concurrent requests and 3.36x at 256, 1.77x on long prompts with a third of the time to first token.
14: - 🟢 **The rig should default to `--data-parallel-size 4 --tensor-parallel-size 1`.** The image supports it on TPU:
15:   tpu_inference resolves it to `TPU_MULTIPROCESS_DP=1`, starts four engine processes each pinned to one chip
16:   (`TPU_VISIBLE_CHIPS=0..3`, `TPU_CHIPS_PER_PROCESS_BOUNDS=1,1,1`), and runs four API servers on port 8000.
17: - ⚠️ At 1 request DP=4 gives 0.93x of one chip and TP=4 gives 1.08x; one engine handles each request, so a lone
18:   request gets one chip's speed in any data-parallel layout.
19: - ⚠️ Each DP engine holds 333,344 KV tokens, the one-chip pool. TP=4 holds 631,968 in one pool, which only matters
20:   for a single request longer than 333k tokens; `--max-model-len` is 16,384.
21: - 🟢 **TP=1, TP=2 and TP=4 give the same output within 11%.** A one-chip server here matches the v5e-1 sibling's
22:   same-method boot (174.7 / 581.1 / 1,386.0 at 1 / 4 / 16), so TP=4 is about one chip's worth of serving spread over four.
23: - ❌ **Splitting does not shorten the step because the attention decode kernel does not shrink.** Per chip it costs
24:   803 ms of a 1,461 ms burst at TP=1, 839 at TP=2 and 831 at TP=4. E2B has one KV head, so every chip holds and reads
25:   the whole KV cache. Matmul time does split (443 → 230 → 130 ms) and collectives add back 206 ms at TP=2 and 243 at
26:   TP=4, so the two cancel.
